Kind: feature

- **A Queue that cannot be reached says so, instead of showing zero.** When the Queue server stops answering, the page now says "Can't reach the Queue server: numbers unavailable", when it was last seen, and keeps the last known numbers greyed out. Before, an empty-looking page could read as an idle queue while runs were running and waiting. The footer says it too, with no numbers.
- **A command that waits is refused.** A command that sleeps, watches, polls in a loop until a condition holds, or reads the machine's load (`uptime`, `sysctl vm.loadavg`, `/proc/loadavg`) is no longer queued: the queue already waits for a quiet machine, and a waiting command held one of its slots doing nothing while everyone else waited. The refusal says so. It applies the same way to `queue_run`, to `kehikot-queue run` and to the guard agents' hooks enforce.
- **A run that holds its slot doing nothing is flagged.** When a running command's processes have used almost no CPU for several minutes, the Queue page and `queue_status` mark it "idle in its slot", so the person can cancel it. Nothing is cancelled on its own.
