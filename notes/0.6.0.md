- **Mark a failed run as seen.** Each run that still needs you has a "Mark as seen" press, and "Mark all seen" clears them at once — for this project, or for every project at This computer. The run stays in the list.
- **A failure in view counts as seen.** A run that still needs you, sitting in view on the visible Test runs page for a moment, stops asking by itself. A hidden page is not being looked at.
- **A later green run clears the red one.** When a run passes, every earlier failure of the same work — same folder, branch and label, "(rerun)" aside — is marked seen and says which run superseded it.
- **Expected failures don't ask.** `queue_run` (and the CLI's `--expect fail`) says a run is meant to fail: its failure is reported as "failed as expected", and a pass asks you instead ("expected to fail but passed").
- **A failure the asking session has already read asks quietly.** Once `queue_wait` has handed the result to the session that asked, its Inbox row is low priority instead of normal.
- **Agents can clear their own failures.** A new `queue_seen` tool marks one run (by id) or all of a place's runs (with `all: true`) as seen, for the runs that session asked for.
